= v0.7.0への移行

v0.7.0では、見出しIDのsource rangeを公開し、lossless text modelの返却型を`text` facadeから
直接importできるようにした。AsciiDoc table cell内のsource blockも文書rootと同じ最終semantic型へ
正規化する。HTML、projectionおよびWASM protocolのfield構造は変更しない。

== 必要な環境とバージョン

ソースからv0.7.0をビルドする場合はRust 1.97.1以上が必要です。配布済みのバイナリだけを使う場合は
Rustは必要ありません。パッケージとRustのバージョンはxref:../release-manifest.json[release manifest]で
確認できます。

Rust、CLI、LSP、WASM、browser package、Zed拡張およびprojectionは、完全一致する`0.7.0`を組み合わせる。
異なるpackage versionの生成物を混在させない。

== Rust公開APIの変更

`semantic::HeadingId`へ`id_range: TextRange`を追加した。明示anchorが見出しへ付く場合はanchor IDのrange、
自動IDの場合は見出し本文のrangeである。全fieldを指定するstruct literalは`id_range`を追加する必要がある。
pattern matchingだけを行う場合は、将来fieldが増えてもよい箇所で`..`を使用する。

[source,rust]
----
use adocweave::semantic::HeadingId;

let HeadingId { id, id_range, .. } = heading;
----

`adocweave::text`は、`SourceDocument::lines()`、`SourceDocument::tokens()`および
`SyntaxKind::Token`の公開返却型をすべて名前解決できるよう、次を再公開する。

* `LineEnding`
* `SourceLine`
* `LosslessToken`
* `LosslessTokenKind`

これらの型を内部module pathから参照してはならない。

== Semantic blockの正規化

最終的な`Document`では、source blockを置き場所にかかわらず
`Block::Verbatim`と`VerbatimKind::Source`で表す。v0.6.xでは`a` styleのtable cellを再帰走査した場合だけ
parser専用の`Block::Source`が残ることがあった。table cellを独自に再帰走査する利用側は、
root blockと同じ`Block::Verbatim`分岐を使用する。

lossless syntax treeは引き続き`SyntaxKind::SourceBlock`を保持する。この変更はHTMLまたはprojectionの
source block表現を変更しない。

== 更新手順

. 同じv0.7.0 ReleaseのCLI、LSP、browser archiveおよびZed archiveを同時に導入する。
. Rust hostで`HeadingId`を全field構築・分解している箇所を更新する。
. table cellを再帰走査する処理から、最終文書の`Block::Source`を前提とする分岐を削除する。
. lossless line／token型は`adocweave::text`からimportする。
. package versionを照合するWASM／browser request、cache keyおよび保存済みmetadataを`0.7.0`へ更新する。
. 保存済みHTML、projection、検索情報およびconformance snapshotを再生成する。
