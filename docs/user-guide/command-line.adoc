= コマンドライン

この文書では、``adocweave``によるAsciiDocファイルの変換、プレビュー、確認および整形を説明します。
入力ファイルを指定しない場合は標準入力を読み、結果を標準出力へ書きます。

== よく使うコマンド

[cols="1,3",options="header"]
|===
|コマンド |用途

|`adocweave convert manual.adoc`
|HTMLへ変換します。

|`adocweave preview manual.adoc`
|ブラウザー向けのローカルプレビューを起動します。

|`adocweave check manual.adoc`
|書式やリンクなどの問題を確認します。

|`adocweave format manual.adoc`
|整形後の内容を標準出力へ書きます。``--check``を付けると、変更が必要かだけを確認します。

|`adocweave symbols manual.adoc`
|見出しなどの構造をJSONで出力します。
|===

[#diagnostics]
== 診断

``check``は文書の問題を位置、重要度、安定したcodeおよびmessageとともに表示します。
自動処理では``--format json``、``--format github``または``--format sarif``を指定し、変更される可能性があるmessageではなく
codeを判定に使用してください。``--json``は``--format json``の互換aliasです。
同じ入力、設定およびパッケージバージョンからは同じ順序で問題を返します。
``--include``を使用した場合も、問題の位置は展開後の仮想文書ではなく、
問題がある元ファイルのパス、行および桁として表示します。

``--format json``は、問題1件を1つのobjectとして配列で返します。すべてのobjectが同じ項目を持ちます。
``sourceId``は問題がある元ファイル、``related``は関連位置、``fixes``は自動修正候補です。
該当がない場合、``related``と``fixes``は空の配列、``sourceId``は``null``になります。
``--include``の有無、入力ファイルの数および参照先の検査結果によって項目が増減することはありません。
参照先の検査で報告する問題は、これらに加えて``target``、``line``および``column``を持ちます。

``asciidoc-file-link``は、``.adoc``または``.asciidoc``で終わる文書を``link``で参照した場合に、
``xref``の使用を提案します。``non-asciidoc-xref``は、`.json`、`.toml`、``.pdf``など、
AsciiDoc以外の拡張子を持つファイルを``xref``で参照した場合に、``link``の使用を提案します。
拡張子は大文字小文字を区別せず、queryとfragmentを除いて判定します。対象ファイルの実在性は検査しません。
schemeのない相対の参照先を明示macroで記述し、参照先に属性参照がない場合に限り、
macro名だけを置換する自動修正を提示します。

通常の``check``はファイルシステムへアクセスせず、``../guide.adoc``のような相対リンクと文書間参照を
有効な対象として扱います。HTMLへ変換する際は、記述されたURLと解決済みURLを出力用ポリシーで
改めて検査します。

[#check-exit-status]
=== 終了状態

終了コードは、失敗の理由ごとに次の値を返します。CLIとLanguage Serverで同じ値を使うため、
どちらを実行したかによって意味が変わりません。

[cols="1,4"]
|===
| コード | 意味

| 0 | 処理が完了し、しきい値に達した診断がありません
| 1 | 診断がしきい値に達しました
| 2 | 指定した引数またはオプションを実行できません
| 3 | ファイル、ストリームまたはリソースの読み書きに失敗しました
| 4 | 入力サイズまたはリソースの上限を超えました
|===

「失敗したかどうか」だけを見る場合は、これまでどおり0とそれ以外で判定できます。値を見分ける必要があるのは、
たとえばコマンドの書き間違い（2）と対象ファイルの不在（3）を別々に扱いたい場合です。

Language Serverは、``shutdown``を受け取る前に``exit``を受け取った場合だけ1を返します。これはLanguage Server
Protocolが定める値であり、上の規約より優先します。

``--fail-on error``はerrorが一件以上、``--fail-on warning``はerrorまたはwarningが一件以上ある場合に
終了コードを1にします。既定値は``error``です。``--fail-on never``は診断の重要度によって失敗させず、
入力、設定またはI/Oのerrorだけを失敗として扱います。human、JSON、GitHub Actions annotationおよびSARIFの
形式を変えても診断集合と終了状態は変わりません。

``--summary``は重要度別件数を標準エラー出力へ書きます。診断本体は標準出力のままなので、JSONを
壊しません。

[source,console]
----
adocweave check --fail-on warning --format json --summary docs
adocweave check --fail-on warning --format github docs
adocweave check --fail-on warning --format sarif docs > adocweave.sarif
----

GitHub ActionsではRelease assetのバージョンを固定し、``--format github``を使用します。更新時は新しい
バージョンを別のディレクトリで検証してから切り替えてください。

相対リンク、文書間参照、画像などのリソースおよびincludeの実在性を検査する場合は、
``--local-targets``と``--project-root DIR``を指定します。

[source,console]
----
adocweave check --local-targets --project-root . docs/manual.adoc
----

この検査は記述元ファイルの親ディレクトリを基準にし、正規化後もproject root内にある``..``を許可します。
絶対パス、外部URL、文書内anchorおよびscheme付きの参照先は対象外です。欠落、project root外への移動、
ディレクトリ、権限不足および検査できない参照先は、安定したcodeを持つerror診断となります。これらはほかの
診断と同じくerror件数へ加算されるため、終了コードは``--fail-on``の設定に従います。``--fail-on never``を
指定した場合は、これらの診断があっても終了コードは0です。
同じファイルへの複数の参照は位置ごとに報告しますが、ファイルシステムの検査結果はコマンド内で共有します。
一意な参照先の検査件数は``resources.max-files``を上限とし、超過した参照先には
``local-target-limit-exceeded``を報告して、それ以降のファイルシステム検査を行いません。この上限は、
一つの文書が要求できるファイルシステムの作業量を制限するものであり、OSによって変わりません。
標準入力の基準ディレクトリはproject rootです。

Linuxでは、project rootのディレクトリハンドルを基準にパスの構成要素を一つずつ開く``HandleRelative``方式を
使用し、検証後のパスを名前から開き直す競合を避けます。検査の最中に、ほかのプロセスがパス上のディレクトリを
移動したりmountしたりすると、kernelはその検査を安全に完了できないと判断して中断します。この場合は同じ検査をやり直します。
やり直しの回数には上限があり、変更が続いて完了できない場合は``local-target-unverifiable``を報告します。
macOSとWindowsでは``StaticSnapshotOnly``方式を使用します。
この方式は、検査中にワークスペースを同時変更しない、信頼済みのワークスペースだけを対象とします。信頼できない入力を
検査する場合は、書換え不能なスナップショットへコピーしてから実行してください。

方式が異なるのはパスの解決方法だけです。検査件数、読み込むバイト数および一つのリソースの大きさに対する
上限は、どちらの方式でも同じように働きます。あるOSで拒否される文書は、ほかのOSでも拒否されます。

利用可能な規則は文書を読み込まずにJSONで取得できます。

[source,console]
----
adocweave check --list-rules --json
----

出力には``schemaVersion``、``packageVersion``およびcode順の``rules``を含めます。各規則の
`code`、`defaultSeverity`、`enabledByDefault`、``userConfigurable``および``fixable``は
自動処理に使用できます。
``description``は表示用であり、判定条件には使用しません。

既定で無効な規則は``--enable-rule CODE``で有効にできます。このoptionは反復して指定できます。
``macro-boundary``は、対応するinline macroが開始境界だけを満たさず通常のtextとして扱われた場合に
warningを返します。

[source,console]
----
adocweave check --enable-rule macro-boundary document.adoc
----

対象は``xref``、`link`、数式、passthrough、標準inline macro、URLおよびemailの完全な構文です。
診断はmacro名を示し、直前がASCII英数字の場合だけ、空白を挿入する確実ではない修正候補を返します。
短縮xref、block macro、不完全またはescapeされた構文、comment、sourceおよびliteral block、
ほかの不透明なinline構文の内部は対象外です。任意の``subs``属性による置換設定は現在対応していません。

[#formatting]
== 整形

``format``は整形後の内容を標準出力へ書き、入力fileを直接変更しません。
``--check``を指定すると内容を出力せず、変更が不要なら終了コード0、必要ならそれ以外を返します。

複数のファイル、ディレクトリまたは``--glob PATTERN``を指定すると、正規化したパスの順に重複なく処理します。
ディレクトリでは``.adoc``だけを再帰的に選び、symlinkはたどりません。複数入力の整形では
`--check`、``--diff``または``--write``のいずれか一つが必須です。

[source,console]
----
adocweave format --check docs
adocweave format --diff --glob 'docs/**/*.adoc'
adocweave format --write docs README.adoc
----

``--write``は全fileを読込・解析した後、元fileと同じディレクトリに一時fileを作り、内容を同期してから
置換します。書換え直前に元のbyte列が変わっていた場合は置換しません。ファイルの実行権限、既存の主な改行形式
および最終改行は、プロジェクト設定で明示的に変更していない限り保持します。一時fileの準備前に
エラーが発生した場合は一件も変更しません。置換開始後の入出力エラーでは、それ以前に置換済みのファイルだけが
更新される可能性があります。各fileの置換自体はatomicです。

``--dry-run``を``--write``と併用すると書換えません。``--summary``は対象数と変更数を標準エラー出力へ
書きます。

整形対象は、安全に意味を保持できる段落と空行に限定します。行末空白、連続空行、改行形式および
最終改行を正規化する一方、literal、source、数式、macro、inline書式、見出し、属性、anchor、list、
未対応構文および不完全な構文は元のbyte列を保持します。同じ入力を繰り返し整形しても結果は変わりません。

== 安全な自動修正

``check --fix``は、診断が``Applicability::Always``として提供する修正だけを適用します。全fileの
修正候補を検証してから``format --write``と同じatomic置換を使用します。複数診断のeditが重複または
交差する場合は、そのfileを書き換えずerrorにします。``Maybe``の修正はCode Actionや差分を確認して
適用してください。``--dry-run --summary``では書換えず、修正対象file数を``changed``として表示します。

[source,console]
----
adocweave check --fix docs
adocweave check --fix --dry-run --summary docs
----

== 色とshell completion

``--color auto|always|never``でhuman診断と差分のANSI色を制御します。既定の``auto``は標準出力がterminalの
場合だけ色を付け、JSONとGitHub Actions annotationには常に色を付けません。

completion scriptは標準出力からshellの設定へ保存します。

[source,console]
----
adocweave completion bash
adocweave completion zsh
adocweave completion fish
adocweave completion powershell
----

== ローカルファイルの展開

ローカルファイルの展開は``--include``を指定した場合だけ有効になります。

[source,console]
----
adocweave convert --include docs/manual.adoc
adocweave check --include docs/manual.adoc
----

ファイル入力では、``--base-dir``を省略するとroot文書の親ディレクトリを基準にします。
標準入力は位置を持たないため、``--include``と同時に``--base-dir DIR``が必須です。
``--allow-root DIR``は複数指定でき、省略時はbase ディレクトリだけを許可します。

[source,console]
----
adocweave convert --include --base-dir docs --allow-root docs - < root.adoc
----

参照先はbase directoryからの相対パスに限定します。
絶対path、`..`、scheme付きtarget、制御文字および許可root外へ解決されるsymlinkを拒否します。
通常linkと異なり、include targetの``?``と``#``はURL成分として分離せずfile名の一部として扱います。
個別のリソースは10 MiB、リソース全体は50 MiB、ファイル数は10,000件を上限とします。
循環、include深さ、展開nodeおよび展開後byte数にはコアpreprocessorの上限も適用します。
ネットワーク上のリソースは取得しません。

`convert`、``check``および``symbols``は同じ展開スナップショットを使用します。
``check``の診断は元resourceの論理的な``SourceId``、行、columnへ投影します。Include resourceには
``include:``で始まるIDを使用し、正規化したパスは診断へ公開しません。
``format``はincludeの展開先を安全性検査しますが、展開結果をrootのファイルへ書き戻さずroot入力だけを整形します。

``check --include --local-targets --project-root DIR``では、includeの読み取りとほかのlocal targetの
実在検査が同じキャッシュと上限を使用します。この組み合わせでは、正規化後もproject root内に収まる``..``を
許可し、``--allow-root``は使用しません。``optional``を指定したincludeの欠落はerrorにしません。

== ローカルプレビュー

``preview``は完全なHTML文書を生成し、既定では``127.0.0.1:4000``で配信します。
``127.0.0.1``は、同じ端末からだけ接続できるループバックアドレスです。
コマンドが表示したURLをWebブラウザーで開いてください。Webブラウザーは自動では起動しません。
終了する場合は、コマンドを実行した端末でkbd:[Ctrl+C]を押します。

[source,console]
----
adocweave preview --include manual.adoc
adocweave preview --port 8080 --css theme.css manual.adoc
----

既定のポートをほかのプログラムが使用している場合は、``--port``で空いているポートを指定します。

起点文書、includeで読み込んだ文書、まだ存在しないinclude対象およびCSSの作成、変更、削除を監視します。
ファイルの更新時刻、長さおよび種類を定期的に確認します。内容の長さと更新時刻が
変わらない編集も検出するため、内容のハッシュ値も定期的に確認します。変更を検出した後に
``--debounce-ms``の待ち時間を適用します。
``--debounce-ms``は、連続した変更を一回の更新としてまとめる待ち時間をミリ秒で指定します。
各更新には単調に増える更新番号を付け、処理が完了したうち最も新しい内容だけを表示します。
監視対象は解析済みの依存関係に限定し、ファイルシステム全体は探索しません。

配信するURLは、表示画面、生成した文書、更新番号、診断および固定のクライアントスクリプトだけです。
任意のファイルの配信、ディレクトリ一覧およびパスを使った配信範囲外への移動は提供しません。
HTTP応答にはContent Security Policy（読み込める資源を制限するHTTPヘッダー）、``no-store``および
内容からファイルの種類を推測させないヘッダーを付けます。
``--css-url``で検証済みの``http``または``https`` URLを指定した場合は、その送信元だけを
Content Security Policyの
``style-src``へ追加します。
ループバック以外のIPアドレスを使用する場合は``--bind ADDRESS --allow-external``を明示する必要があり、
ほかの端末から生成内容を閲覧される可能性がある旨を警告します。プレビューサーバーは利用者認証と
TLSによる通信の暗号化を提供しません。信頼できないネットワークへ直接公開しないでください。
includeとCSSには``convert``と同じプロジェクトの基準ディレクトリ、資源の上限およびHTML出力方針を
適用します。

プレビューサーバーはHTTP処理の同時実行数、待機数、request headerの長さおよび通信時間に
上限を設けます。実行中と待機中の枠がすべて埋まった場合は、新しい接続を応答せずに閉じます。
Webブラウザーは次の更新確認で再接続します。

kbd:[Ctrl+C]または新しい変更を検出すると、実行中の生成処理へ停止を通知します。解析処理は停止通知を
直接確認できます。includeの準備、ファイルの読み取りおよびHTMLの生成など、処理中に停止通知を確認しない段階は
その段階が完了するまで待ち、次の段階へ移る境界で終了します。

== 完全なHTML文書とCSS

``convert``は既定でHTML fragmentを出力します。``--complete``を指定すると完全なHTML文書を出力し、
``--css FILE``と``--css-url URL``でstylesheetを``<head>``へ追加できます。どちらも複数回指定でき、
指定順に出力します。CSSは出力設定であり、文書入力の``style``属性や任意classは引き続き拒否します。

[source,console]
----
adocweave convert --complete --css theme.css --css-url https://example.com/print.css manual.adoc
----

``--css``と``--css-url``は``--complete``が必須です。CSS fileはUTF-8で、1 sourceあたり1 MiBを上限とします。
`</style`、``<!--``または改行・タブ以外の制御文字を含むCSS本文、URL policyが拒否するURL
（既定は``http``と``https``だけ）および上限超過は、部分的なHTMLを出力せずエラーで終了します。
