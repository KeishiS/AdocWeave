= AsciiDocとの互換性

この文書では、AsciiDocおよびAsciidoctorに対するAdocWeaveの意図的な違いを説明します。
AdocWeaveはAsciiDoc全体やAsciidoctor固有機能の再現を目的としません。
対応範囲は xref:syntax-support.adoc[対応しているAsciiDocの書式]、
実装する文法は xref:../developer-guide/grammar.adoc[文法の詳細]を基準とします。

参照する標準仕様は以下のとおりです。

* https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc Language documentation]
* https://docs.asciidoctor.org/asciidoc/latest/_exports/asciidoc-pre-spec.pdf[AsciiDoc pre-specification, 2026-02-03版]

== 意図的な違い

[cols="2,4",options="header"]
|===
|領域 |AdocWeaveの動作

|未対応構文
|``permissive``モードでは元の内容を保持し、``strict``モードではコア操作を拒否します。

|語間に空白を置かない文字の前後で、記法が要求した空白
|日本語、中国語、韓国語のように語を空白で区切らない文字の直後では、記法が要求した空白をHTMLへ
出力しません。対象は次の2つです。

段落内の改行は、仕様では空白1つに変換されます。改行の前後がどちらもこれらの文字である場合は、
空白を出力せずに行をつなぎます。原文のどこで折り返したかが本文の空きにならないようにするためです。

inline macroは、直前に空白がなければmacroとして認識されません。この空白の直前がこれらの文字で
ある場合は、空白を出力しません。macroの直前は、著者が空白を省けない唯一の位置です。

macroの直後の空白と、書式記号の前後の空白は出力します。macroの直後は空白を書かなければ済み、
書式には空白を必要としない書き方（``**強調**``のような二重記号）があるため、そこにある空白は
著者が選んで書いたものだからです。

判断に使うのは空白の直前にある地の文の文字だけで、macroの中身や、macroがHTML要素になるかどうかは
見ません。hostの機能設定で画像を無効にした場合や、相互参照を解決できなかった場合でも結果は同じです。
空白の直前がLatin文字や数字である場合は、空白をそのまま出力します。

|インライン書式
|highlight、subscript、superscript、typographic quoteを含む対応書式について、境界と不完全なマーカーの
回復規則だけを保証します。制約付き等幅表記の境界を満たさない単一バッククォートの対は、
等幅として認識せず、通常テキストと診断に回復します。AsciiDoc処理系すべてとの同一結果は保証しません。

|Passthrough
|置換を抑止する不透明なノードとして保持しますが、生のHTMLとして出力せずHTMLエスケープします。

|Quoteとverse
|styleなしの``____``は入れ子を許すブロックとして扱い、``[quote,Author,Source]``だけを``blockquote``として出力します。
``[verse]``は改行を保持し、内容のインライン書式を解釈しません。

|Admonition
|admonition paragraphとadmonition blockを型付き意味として扱い、未知のstyleは通常のブロックとして保持します。

|表
|PSV／CSV／DSV／TSVと対応する表示属性を扱います。AsciiDoc style cellのブロック解析はPSVを対象とし、
開始区切り直後の単一物理行と後続の空行によるheader推論に対応します。複数物理行の先頭行は
``header`` optionで明示します。

|ソースブロック
|`linenums`、`%linenums`または``options=linenums``と、同時に指定した1以上の``start``を扱います。
その他のsource option、行番号の描画、テーマおよびコピー操作には対応しません。

|相互参照とリソース
|文書間xrefとメディアの実在確認、取得および権限検査を行わず、利用側アプリが解決結果を渡します。
メディアのactive要素にはmacro種別と一致するMIME typeを必須とし、video posterも独立した画像リソースとして
解決します。メディアのリンク化とicon set固有の表示には対応していません。

|Preprocessor
|利用側アプリが渡す不変のリソーススナップショットだけを展開します。ワイルドカードとURI転送には対応しません。

|Markdown互換構文
|AsciiDoc標準の必須範囲ではないため対応しません。
|===
