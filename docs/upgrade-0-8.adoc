= v0.8.0への移行

v0.8.0ではLanguage Serverのlifecycle、client capability negotiationおよびworkspace連携を
Language Server Protocol 3.18へ合わせた。Rust公開API、HTML、projectionおよびWASM protocolの
field構造は変更しない。

== 必要な環境とバージョン

ソースからv0.8.0をビルドする場合はRust 1.97.1以上が必要です。配布済みのバイナリだけを使う場合は
Rustは必要ありません。パッケージとRustのバージョンはxref:../release-manifest.json[release manifest]で
確認できます。

Rust、CLI、LSP、WASM、browser package、Zed拡張およびprojectionは、完全一致する`0.8.0`を組み合わせる。
異なるpackage versionの生成物を混在させない。

== Language Serverの変更

初期化時にclient capability profileを確定し、次の応答と広告をclientの対応範囲へ合わせる。

* HoverのMarkdown／Plain Text
* 階層または平坦なDocument Symbol
* Code Action literalと`isPreferred`
* version付き`documentChanges`とdiagnostics
* Document Link tooltip
* full Semantic Tokens

workspace folder対応clientでは、初期folder集合と`workspace/didChangeWorkspaceFolders`を扱う。
watched filesの動的登録に対応するclientには、`**/*.adoc`のcreate、changeおよびdeleteを
`client/registerCapability`で登録する。登録を拒否された場合もLanguage Serverは継続する。

initialize前、重複initializeおよびshutdown後のrequestはLSP 3.18で定められたerrorとなる。
shutdown後のexitだけが終了status 0となり、それ以前のexitはstatus 1となる。
initializeの`processId`が指定された場合はclient processの終了を監視する。

== Client実装への影響

標準的なLSP clientでは設定変更を必要としない。独自clientまたはtest harnessは、次を確認する。

* 使用する応答形式に対応するclient capabilityをinitializeで宣言する。
* `initialized`通知後に届く`client/registerCapability` requestへ応答する。
* workspace folder対応を宣言した場合、`workspaceFolders: null`は空集合として扱われ、
  `rootUri`へfallbackしないことを前提とする。
* `shutdown` responseを待ってから`exit`を送る。
* request IDには整数または文字列を使い、JSON-RPC batchを送らない。

`async-lsp 0.2.4`のcodecはmalformed JSONまたはinvalid request objectで接続を終了し、
`ParseError`または`InvalidRequest` responseを合成しない。この制約を含む完全な対応表は
xref:../issues/162-lsp-3-18-conformance-audit.adoc[LSP 3.18適合性監査]を参照する。

== 更新手順

. 同じv0.8.0 ReleaseのCLI、LSP、browser archiveおよびZed archiveを同時に導入する。
. 独自LSP clientのinitialize capabilityと動的登録への応答を確認する。
. lifecycle testが`initialize`、`initialized`、`shutdown`、`exit`の順序を守るよう更新する。
. package versionを照合するWASM／browser request、cache keyおよび保存済みmetadataを`0.8.0`へ更新する。
. 保存済みHTML、projection、検索情報およびconformance snapshotを再生成する。
