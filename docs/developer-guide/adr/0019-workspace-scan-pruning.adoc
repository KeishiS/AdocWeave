= ADR 0019: 初期ワークスペース走査とリソース読込の分離

== 状態

採用

== 背景

Language Serverは、ワークスペース内の``.adoc``ファイルを解析の起点として登録するため、起動時に
ディレクトリを再帰的に走査します。仮想環境、依存パッケージおよびビルド結果を含むワークスペースでは、
解析対象ではないファイルによって10万件の走査上限へ達することがあります。

走査からディレクトリを除外するだけでは、除外したディレクトリ内の文書をincludeできなくなります。
一方、除外規則をファイルシステムのアクセス権限として扱うと、明示的に開いた文書やCLI入力にも影響し、
初期走査の負荷を抑えるという目的を超えて既存の動作を変えてしまいます。

== 決定

``workspace.scan.exclude``は、Language Serverの初期ディレクトリ走査で解析の起点を見つける処理だけに
適用します。各workspace folder直下の設定を走査前に読み、一致した実ディレクトリを内容の列挙前に
枝刈りします。除外したディレクトリ自体は既存の走査件数へ数え、その中身は数えません。

patternはOSに依存しない規則で検証し、ワークスペースのルートからの相対位置へ照合します。区切りは``/``、
照合は大文字と小文字を区別し、``*``と``?``は一つの区間、単独の``**``は複数の区間に一致します。
絶対パス、親ディレクトリへの移動およびOS固有の区切りは拒否します。

除外規則はファイルシステムのアクセス権限ではありません。明示的に開いた文書、CLIへ直接渡した入力、
file watcherが通知した文書およびinclude先には適用しません。初期走査で見つけた解析の起点を前処理し、
includeに必要な文書がsnapshotにない場合だけ、従来のworkspace root、``resources.roots``、symlink検査および
resource上限を使って読み込みます。読み込んだinclude先は解析の起点として登録しません。

directoryの列挙と走査件数の管理は引き続き``adocweave-host``が所有します。設定の照合結果は、
ディレクトリを列挙する前に呼ぶ判定関数としてhostへ渡します。parser、HTML compilerおよびCLIは
この判定関数を渡さないため、入力の選択方法は変わりません。

== 結果

利用者は大きな生成物のディレクトリを初期走査から除外しながら、必要な文書を明示的に開くかincludeできます。
10万件という安全上限と、ファイルシステムへのアクセスを制限する既存の境界は維持されます。

走査前にworkspace folder直下の設定を読む経路と、include先を必要に応じて追加する経路が増えます。
設定変更またはworkspace folder変更が起きた場合は、進行中の古い走査結果を無効にする必要があります。
