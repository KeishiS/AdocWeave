= ADR 0006: stable tagへの直接公開
:status: accepted

== 文脈

このrepositoryは個人開発であり、stable公開前の候補成果物に対して導入、完全性および由来を
自動検証します。RCとstableを別tagで公開すると、同等の検証とバージョン同期を二度運用する一方、
追加の独立した受け入れ情報は得られません。

== 決定

release candidate tagを受理しません。すべてのrelease対象変更を``main``へ統合した後、手動workflowに
その先端commitを候補SHAとして渡します。workflowは候補SHAがdispatch開始時点のmain先端と一致することと、
同じSHAのmain candidateの成功を検証し、そのSHAを公開対象として固定します。

検証後は公開jobが``vX.Y.Z`` tagを一度だけ作成し、同じworkflow runでstable GitHub Releaseを公開します。
公開後の修正はtagを付け替えず、新しいstableなバージョンとして公開します。

書き込み権限はworkflow tokenが持ちます。``github-release`` Environmentが、その権限を使える範囲を限定する
権限・監査境界です。release用workflowで``contents: write``を持つjobはこの公開jobだけであり、Environmentの
deployment branch制限によって、許可したbranchから開始したrunだけがこのjobへ到達します。

``v*``を対象とするtag rulesetがtagの作成、更新および削除を制限し、組み込みのGitHub Actions appだけを
bypass対象とします。人が手元からstable tagをpushすることは機械的に拒否されます。このbypassはworkflow全般に
及びますが、release用workflowで``contents: write``を持つjobは公開jobだけであり、Environmentのdeployment
branch制限と合わせてtagの作成経路を公開jobへ限定します。専用のpublisher用GitHub Appを唯一のbypass対象と
すればより厳密になりますが、Appの作成、インストールおよび鍵の管理という運用費用が個人開発では
見合わないため使用しません。

== 帰結

公開経路はstable SemVerだけを扱います。tag作成前の自動検査を公開条件とし、
公開後の修正は新しいバージョンで行うため、tag後の検査結果でtagを変更しません。
公開開始後に人が承認を挟む停止点はありません。候補SHAを指定した``workflow_dispatch``を公開判断とし、
その開始時点でmain先端だった候補SHAを以後の公開identityとして扱います。
開始後にmainが進んでも候補SHAと成果物は差し替えません。
未知の環境での長期試験が必要になった場合だけ、通常release trainとは別の検証用branchまたは
事前配布を明示的に設計します。
