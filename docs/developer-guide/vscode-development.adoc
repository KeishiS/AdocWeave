= VS Code拡張の開発

この文書では、リポジトリの作業treeからVS Code拡張とLanguage Serverを検証する手順を説明します。
利用者向けのVSIX導入手順は
xref:../user-guide/release-installation.adoc#vscode-installation[VS Codeへの導入]を参照してください。

== 責務

`editors/vscode/`はAsciiDocのlanguage登録、TextMate grammar、Language Server processの所有および
managed binaryの取得を担当します。解析、診断、整形および意味問い合わせは`adocweave-lsp`だけが実装します。
解析設定は`.adocweave.toml`を正本とし、VS Code設定へ複製しません。

TextMate grammarはLanguage Server起動前の基本色付けを担当します。Semantic Tokensはlink、xref、anchor、
literalなどの意味的な補足を担当し、見出しの基本色付けを置き換えません。

== 自動検証

Nix開発環境で次を実行します。

[source,console]
----
nix develop
cargo make check-vscode
cargo make test-vscode
cargo make test-vscode-extension-host
cargo make test-vscode-release-package
----

Extension host testは固定versionの公式VS Codeを隔離したuser data directoryへ取得し、local buildの
``adocweave-lsp``を絶対pathで指定します。診断、Outline、Code Action、Format、Hover、補完、Definition、
References、Document Link、Rename、Semantic Tokens、UTF-16位置、include先の更新、連続編集後の古い結果の不採用、
複数workspace folder、再起動および終了後のprocess残存を確認します。通常利用しているVS Code profileは使用しません。

``test-vscode-release-package``は同じsourceからVSIXを2回構築し、byte列の一致、許可file一覧、license、
source mapと``node_modules``の不在、sizeおよび機械固有pathの不在を検査します。さらに、隔離したVS Codeへ
VSIXを導入し、更新、以前のversionへのrollbackおよびuninstallを確認します。

== 手動確認

. Language Serverと拡張をbuildします。
+
[source,console]
----
cargo build -p adocweave-lsp
npm ci --ignore-scripts --prefix editors/vscode
npm run build --prefix editors/vscode
----

. 空のprofile directoryを作り、VS Code CLIの``--extensionDevelopmentPath``でExtension Development Hostを
  起動します。``code``は手元で使用するVS Codeの実行fileへ置き換えられます。
+
[source,console]
----
mkdir -p /tmp/adocweave-vscode-user /tmp/adocweave-vscode-extensions
code \
  --user-data-dir /tmp/adocweave-vscode-user \
  --extensions-dir /tmp/adocweave-vscode-extensions \
  --extensionDevelopmentPath="$PWD/editors/vscode" \
  "$PWD/editors/vscode/test/fixtures/adocweave.code-workspace"
----
. Extension Development Hostの利用者設定へ次を追加します。
+
[source,json]
----
{
  "adocweave.server.path": "/absolute/path/to/target/debug/adocweave-lsp",
  "adocweave.server.download": false
}
----

. ``test/fixtures/workspace/root.adoc``を開き、自動検証と同じ機能を確認します。
. Output panelの``AdocWeave``を確認します。拡張独自のlogには文書本文、URI、環境変数およびdownload URLを
  出力しません。Language Client traceは既定で無効です。

== Language Serverの選択

次の順序で選択します。

. ``adocweave.server.path``で明示した絶対path
. extension hostの``PATH``上にある互換versionの``adocweave-lsp``
. 検証済みmanaged cache
. 同じversionのGitHub Releaseから取得したmanaged binary

明示pathは``--version --json``に失敗するかversionが一致しない場合に停止し、別のbinaryへfallbackしません。
``PATH``上の不一致は警告してmanaged binaryへ進みます。workspace scopeの明示pathは、
そのworkspaceが信頼済みの場合だけ使用します。引数、環境変数、download先および任意commandは設定できません。

Managed binaryは配布manifestのsource commit、version、target、archive、実行file名、byte数およびSHA-256を
検証します。ZIPは展開量を制限し、絶対path、drive prefix、``..``、大小文字衝突および重複実行fileを拒否します。
検証済みcacheはversion、targetおよびasset digestごとに分離し、起動時にbinary digestを再確認します。

== 清掃

Extension Development Hostを終了するとLanguage Clientへ`shutdown`と`exit`を送り、期限内に終了しない
processを停止します。コマンド`AdocWeave: 管理対象Language Serverを削除`はLanguage Serverを停止してから、
この拡張のglobal storage内にあるmanaged server専用directoryだけを削除します。

自動testの隔離profileはtest runnerが削除します。通常profile全体、共有extension directoryまたは親cacheを
清掃目的で再帰削除しません。
