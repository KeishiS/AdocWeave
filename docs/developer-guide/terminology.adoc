= 用語の表記

この文書では、AdocWeaveの日本語文書で語をどう表記するかを定めます。文書を書くときと、既存の文書を
直すときの基準です。

この方針の目的は、専門分野が異なる学部生でも前から順に読める文章にすることです。日本語の地の文に
英語の一般名詞が混ざると、読み手はそこで一度立ち止まります。一方で、識別子や設定名を日本語へ直すと、
実際に入力する文字列と一致しなくなり、かえって使えなくなります。この二つを分ける基準を以下に定めます。

== 判定の基準

語が原綴りのままか日本語かは、その語が**画面に入力する文字列を指すか**で決まります。

原綴りを保つのは次の場合です。

* 識別子、型名、関数名、フィールド名（``DocumentProjection``、``RenderInputs``、``packageVersion``）
* コマンド、サブコマンド、タスク名（``cargo make verify``、``adocweave check``）
* オプション名、設定キー（``--fail-on``、``resources.max-files``）
* 診断コード、ファイル名、パス（``unresolved-cross-reference``、``.adocweave.toml``）
* 固有名詞と製品名（AsciiDoc、Rust、Nix、GitHub Actions、Language Server Protocol）

日本語にするのは、上のいずれにも当たらない地の文の一般名詞です。同じ綴りでも、指すものによって
扱いが変わります。

[cols="3,3,4"]
|===
| 原綴りを保つ | 日本語にする | 理由

| ``--check``、``cargo check``
| 「検査」「確認」
| 前者は入力する文字列、後者は動作の説明

| ``resources.max-files``
| 「ファイル」
| 前者は設定キー、後者は対象そのもの

| ``packageVersion``
| 「バージョン」
| 前者はフィールド名、後者は版を指す一般名詞

| ``--local-targets``
| 「参照先」
| 前者はオプション名、後者は指し示す対象
|===

== 判断に迷う語

次の語は、指すものが文脈で変わるため、置き換える前に何を指しているかを確かめてください。

`source`:: 入力となるAsciiDoc文書、プログラムのソースコード、`sourceId`のようなフィールド名の一部の
いずれかを指します。文書を指す場合は「文書」または「入力」、プログラムを指す場合は「ソース」、
フィールド名は原綴りです。

`target`:: 参照先、ビルド対象、`--local-targets`が検査する対象のいずれかを指します。
参照を指す場合は「参照先」、ビルドを指す場合は「ターゲット」です。

`check`:: 動作としての検査、``check``サブコマンド、``--check``オプションのいずれかを指します。
動作を指す場合だけ「検査」です。

`profile`:: Cargoのビルドプロファイル、解析プロファイル、実行時のリソースプロファイルを指します。
いずれも設定名に対応するため、原綴りを保ちます。

== 進め方

一括置換は行いません。同じ綴りが識別子と一般名詞の両方に現れるため、置換だけでは識別子を壊します。

文書ごとに、上の基準で1件ずつ判断します。順序はユーザー向け文書を先、開発者向け文書を後とします。
ユーザー向け文書のほうが、専門分野が異なる読み手に届く可能性が高いためです。
