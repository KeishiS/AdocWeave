= 用語の表記

この文書では、AdocWeaveの日本語文書で語をどう表記するかを定めます。文書を書くときと、既存の文書を
直すときの基準です。

目的は、同じ語について毎回判断し直さなくて済むようにすることです。「識別子は原綴り、一般名詞は日本語」
という規則だけでは、``file``と書くたびにどちらに当たるかを導き直すことになり、書き手ごとに結論がずれます。
ここでは、判断が分かれる語について結論を記録します。

AdocWeave固有の考え方を表す語（公開仕様、対応範囲、意味情報など）の意味は
xref:../README.adoc[文書と公開仕様の一覧]で定めます。この文書が扱うのは表記だけです。

== 判定の基準

語を原綴りのまま書くか日本語で書くかは、**その語が画面に入力する文字列を指すか**で決まります。
識別子、型名、コマンド、オプション名、設定キー、診断コード、ファイル名およびパスは原綴りです。
それ以外の地の文の一般名詞は日本語にします。

AsciiDocの構文要素の名前も原綴りです。``admonition paragraph``、`source block`、``delimited block``の
ように、AsciiDoc仕様が定める呼び名を指すためです。これらの一部は``fixtures/syntax-support.json``が
検索文字列として持ち、対応範囲の記述と実装の同期を検査しています。書き換えると検査が失敗します。

== 使わない表現

// textlint-disable adocweave-terminology
次の語は、辞書的には正しくても意味を取り違えさせるため使いません。複合語を含め、この語を含む表現は
すべて対象です。検査対象の一覧は
link:../../config/japanese-terminology.json[`config/japanese-terminology.json`]を基準とします。この文書には、
各項目を避ける理由と、書き直すときの判断基準を記載します。

[#legal-contract-metaphor]
`契約`::
+
--
日本語の「契約」は当事者間の法的な取り決めを指します。ここでの contract は、公開したものを変えないと
いう約束や、二つの設定が一致しているという条件であり、「誰と誰の間の契約か」という問いを読み手に
起こさせます。

何と書くかは、その箇所が何を指しているかによります。公開して維持する範囲、維持することの保証、
設定どうしの整合条件、適合しているかの判定、あるいは``release-contract``のようなtask名の一部と、
指すものが異なります。前後の文と対応する実装を読んでから決めてください。

これまでに見つかった表現です。一覧は網羅ではありません。

公開契約、現行契約、契約項目、互換契約、処理契約、契約判定、release契約、契約fixture、HTML契約、
配布契約、属性契約
--
// textlint-enable adocweave-terminology

この節の規則は``cargo make textlint-repository-prose-lint``で検査します。AdocWeaveが文章として分類した箇所だけを
検査するため、code、URLおよびAsciiDocの構文記号を対象にしません。検査が見るのは禁止語だけで、何に
直すかは書き手が文脈で決めます。正しい表現が一つに定まらなくても検査は成立します。

この文書自身の例は、前後の``textlint-disable``と``textlint-enable``のcommentでプロジェクト用語規則だけを
抑制します。ほかの日本語規則はこの文書にも適用します。

== 判断が必要な語

同じ綴りが識別子にも一般名詞にも現れる語です。書き手の判断が分かれるのはここだけなので、見分け方を
添えます。

[cols="1,2,2"]
|===
| 綴り | 原綴りのまま書く場合 | 日本語で書く場合

| check
| ``--check``、``cargo check``、``adocweave check``、``cargo make check-zed``
| 動作としての「検査」「確認」

| version
| ``schema-version``、``packageVersion``、``--version``
| 版を指す「バージョン」

| target
| ``--local-targets``、``target``ディレクトリ、``local-target-unverifiable``
| 指し示す先としての「参照先」

| file
| ``resources.max-files``、``asciidoc-file-link``
| 対象としての「ファイル」

| source
| ``sourceId``、``source-language``、``figure.source-block``
| 入力となる文書なら「文書」「入力」、プログラムなら「ソース」

| profile
| ``dist`` profile、解析profile、resource profile
| 使いません。いずれも設定名に対応するため原綴りを保ちます

| generation
| ``DocumentRevision``の解析世代、workspaceの有効状態世代、filesystem resource bindingの世代、
  走査回復の世代など、crateごとに別の識別子を指します
| 「世代」。同名で意味が異なるため、文書ではどのcrateのどの状態機械の世代かを必ず特定します
|===

== 単純に置き換える語

このリポジトリに同名の識別子がないため、地の文では常に日本語で書きます。

directory → ディレクトリ、path → パス、package → パッケージ、release → リリース、
workspace → ワークスペース、repository → リポジトリ、branch → ブランチ、commit → コミット、
tag → タグ、cache → キャッシュ、log → ログ、option → オプション、boundary → 境界、
limit → 上限、default → 既定、snapshot → スナップショット、build → ビルド、test → テスト、
runner → ランナー、toolchain → ツールチェーン

診断の重要度を指す``error``と``warning``は原綴りです。それ以外の文脈では「エラー」「警告」とします。

== 進め方

一括置換は行いません。同じ綴りが識別子と一般名詞の両方に現れるため、置換だけでは識別子を壊します。

文書ごとに、上の基準で1件ずつ判断します。順序はユーザー向け文書を先、開発者向け文書を後とします。
ユーザー向け文書のほうが、専門分野が異なる読み手に届く可能性が高いためです。
