= アーキテクチャ

この文書では、AdocWeaveのコンポーネント間の責務と、実装が維持する不変条件を定義します。
公開APIと対応範囲はxref:core-profile.adoc[コアの対応範囲]、
文法はxref:grammar.adoc[文法の詳細]を参照してください。

[source,text]
----
ソーステキスト
  ├─ adocweave-config
  │    └─ version付きの共有設定
  └─ adocweave-workspace
       ├─ disk resourceとopen overlay
       ├─ immutable snapshotと依存graph
       └─ adocweaveによる同一revisionの解析結果
            ├─ losslessな構文情報
            ├─ 出力形式に依存しない意味情報
            ├─ 診断
            └─ 参照・文書構造などの派生情報
                 ├─ FormatterとLint
                 ├─ HTMLその他の出力
                 ├─ CLIとLanguage Server
                 └─ 利用側アプリの拡張
----

== 単一解析

入力は一度解析し、同一revisionの解析結果をFormatter、Lint、HTML、
Language Serverおよび利用側アプリで共有します。
利用側ごとにソースを再解析したり、見出し、参照、文書構造などを独自に再導出したりしません。

解析結果は、入力、設定、構文情報、意味情報、診断および派生情報が同じrevisionに属する
不変なスナップショットです。構築途中の結果を公開せず、公開後に意味情報を変更しません。

== 構文層と意味層

構文層は元のbyte列、改行、空白、区切り記号、不完全な入力および回復地点を保持します。
意味層は見出し、段落、リスト、表、参照、属性などを出力形式に依存しない値として表します。

構文認識ではlosslessな構文情報と意味解析に必要な事実を同時に収集します。
意味解析は文書属性、参照先、アンカーおよび文書全体の構造を一度だけ確定します。
HTMLやエディター固有の表示規則をParserへ持ち込みません。

不完全または未対応の入力も元の範囲を失わない構造として保持します。
回復処理は必ず入力上を前進し、同じ位置を繰り返し処理しません。
具体的な認識規則と回復結果はxref:grammar.adoc[文法の詳細]で定義します。

== 利用側アプリとの境界

コア解析はfilesystem、network、database、環境変数および非同期runtimeへ直接アクセスしません。
外部resourceを必要とする処理は、利用側アプリが安全性と権限を確認したスナップショットをコアへ渡します。

``adocweave-workspace``は、disk resource、open overlay、解析root、include依存graphおよび世代付き
スナップショットをruntime非依存かつI/O非依存の状態機械として提供します。filesystem関連crateへ依存せず、
検証済みのresource IDと本文だけを受け取ります。

Native adapterは``adocweave-host``の``LocalFilesystemSession``を共有します。Linuxではrootの
directory handleを起点にfileを開いてから読み取り、path検査後に別のfileを開き直しません。
初期directory列挙、symlink判定、UTF-8読込およびfile数・byte数の上限も同じsessionが担当します。
論理的なsource ID、不変な本文およびfilesystem provenanceは一つの読込結果として構築します。
依存関係を監視するadapter以外はcanonical pathを利用せず、診断やsource mapの識別子にも使用しません。

``adocweave-config``は、CLIとLanguage Serverが共有する設定schema、探索および型付き設定を提供します。
設定は解析とI/O policyへの入力であり、workspace外へのアクセス権限を追加しません。

利用側アプリは外部resourceの取得、pathやURLの検査、認証、cache、timeoutおよび利用者固有の
参照索引を担当します。コアは渡された入力から決定的な解析結果を生成し、取得処理を呼び戻しません。
詳しい実行順序はxref:server-execution.adoc[利用側アプリの実行仕様]で定義します。

アプリ固有のID、database schema、アクセス制御および検索用metadataは標準の意味情報へ混在させません。
利用側アプリは標準解析後に同じスナップショットから独自情報を検証・投影します。
拡張境界はxref:extensions.adoc[利用側アプリの拡張]で定義します。

== 純粋性と信頼境界

同じ入力、設定、外部resourceのスナップショットおよびpackage versionからは、
同じ解析結果と出力を生成します。時刻、乱数、filesystemの列挙順およびmapの挿入順を結果へ反映しません。

文書入力、外部resourceおよび利用側アプリが返すURLを信頼済みのHTMLとして扱いません。
HTML出力では要素、属性、classおよびURLを許可集合に制限し、各出力文脈に合わせてescapeします。
具体的な出力規則はxref:html-contract.adoc[HTML出力の仕様]で定義します。

処理上限は構造要素や診断の生成前に適用します。上限超過後に無制限の解析を継続したり、
全件生成後の切り詰めだけで資源使用量を制御したりしません。

== 非同期実行

非同期の利用側アプリは、解析対象の文書revisionとworkspace generationを記録します。
結果は両方が現在値と一致する場合だけ採用し、異なる世代の解析結果を合成しません。

CPU解析はprotocolやUIのevent loopから分離し、同時実行数と待機数を制限します。
キャンセルはコア解析へ伝播し、キャンセル済みまたは古い結果を診断、表示、編集およびcacheへ採用しません。
Language Server固有の規則はxref:language-server.adoc[Language Serverの実行仕様]で定義します。

共有状態のlockはスナップショット取得と結果採用判定に限定します。CPU解析、外部I/O、
実行枠の待機およびclient通信中にlockを保持しません。

== 変更時の不変条件

実装変更では次の不変条件を維持します。

* 出力形式、runtimeまたは利用側アプリごとのParserの複製禁止
* 新しい構文要素の追加時における、構文情報、意味情報、診断、Formatter、Lint、出力、
  Language Serverおよびfixtureの扱いの同一変更内での確認
* 未処理要素の明示的な列挙
* 入力長に対する構文認識と回復処理の線形性、および大量の未閉じmarkerに対する
  開始位置ごとの残余入力の再走査禁止
* root文書とinclude文書における前処理規則、処理上限およびsource map規則の共通化
* 外部I/Oを利用側アプリ、決定的な解析と変換をコアが担う責務境界
* 同一入力スナップショットに対するnativeとWASMの意味情報および出力の一致
* command dispatch、byte decoding、出力形式の選択および最終出力のbyte上限に対する利用側アプリの責務

ファイル数や行数だけを理由に新しい層を設けません。分割する場合は、構文認識、意味解析、
出力、protocol変換、実行制御または外部I/Oという責務の違いを明確にします。
