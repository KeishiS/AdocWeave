== 設定で解析規則を追加しない

AsciiDocの言語仕様が定めていない解析規則を、設定で追加することは行いません。次のIssueは、
この判断と検討内容を残す記録として保留します。

* https://github.com/KeishiS/adocweave/issues/384[利用側アプリ用の文書属性の接頭辞の予約]

同じ文書が設定によって異なる意味を持つ状態を作らないためです。AdocWeaveは、文書の意味を
文書自身と言語仕様だけから決めます。仕様が組込み属性として定めた名前は、設定にかかわらず
仕様どおりに解釈します。

利用側アプリが定める属性は、現在も組込みの意味を与えずに属性環境へ保持します。名前が
利用側アプリのものであることは、その名前を決めた利用側アプリが知っています。AdocWeaveが
接頭辞を設定として受け取っても、解釈を変えない点は同じです。

== 仕様と異なる動作を選ぶ条件

前節の判断は、設定によって解釈が変わることを避けるためのものです。設定を伴わず、同じ文書が
常に同じ意味を持つ範囲であれば、仕様と異なる動作を選ぶことがあります。次の条件をすべて
満たす場合に限ります。

* 仕様どおりの動作が、対象とする書き方で実用上の不都合を生むこと
* その不都合を避ける手段が仕様の側にないこと
* 設定ではなく文書の内容だけで動作が決まり、同じ文書が常に同じ結果になること
* 違いが生じる範囲を機械的に判定でき、範囲外の文書では結果が変わらないこと

選んだ場合は、違いとその理由をxref:../user-guide/compatibility.adoc[AsciiDocとの互換性]へ
記載します。仕様どおりの結果を期待する読者が、どこが異なるのかを一覧で確認できるように
するためです。

現在この条件で選んでいるのは、語を空白で区切らない文字の直後で、記法が要求した空白を出力しない
動作です。仕様は段落内の改行を空白へ変換し、inline macroは直前の空白がなければmacroとして
認識しませんが、日本語や中国語ではその空白が本文の空きとして現れます。

対象は、著者が空白を省けない位置に限ります。macroの直後は空白を書かなければ済み、書式には
空白を必要としない書き方があるため、そこにある空白は著者が選んだものとして残します。この線引きが
4つ目の条件、つまり範囲を機械的に判定できることに当たります。
