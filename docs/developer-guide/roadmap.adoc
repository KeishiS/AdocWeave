この文書では、現在進行中の作業と着手を予定している作業の方向を示します。実施時期や公開日を
約束するものではありません。各作業の詳しい内容、依存関係および完了条件は、リンク先の

完了した作業の経緯はIssue、バージョンごとの変更は
https://github.com/KeishiS/adocweave/releases[GitHub Releases]のRelease Notesに記録します。
このページには完了したmilestoneの履歴を残しません。

== textlint連携の責務分離

公開済みのAsciiDoc Processorについて、TxtAST変換と配布工程の責務を整理します。
正しさと使用量の上限に関わる変換backendを先に再設計し、その出力仕様を基準に配布工程を整理します。

* https://github.com/KeishiS/adocweave/issues/435[textlint adapterの型付きTxtAST backend]
* https://github.com/KeishiS/adocweave/issues/436[textlintプラグインの配布工程とconsumer fixtureの分離]

後者は前者が定めるpackage構成と実行条件へ依存します。いずれも、parser、HTML変換、Language Serverおよび
Browser向けWebAssemblyの公開動作を変更せず、textlint専用境界だけを対象とします。

以下は、着手するかどうかの判断が先に必要な項目です。判断の材料が揃うまで実装へ進みません。

保留しています。

* https://github.com/KeishiS/adocweave/issues/84[公式Playground]

公式Playgroundの公開には、配信先、公開URL、公開作業を行う権限および問題発生時に以前の状態へ戻す

製品バージョンの更新やほかの機能を公開するための前提にはしません。

== 実施しない解析規則の追加

AsciiDocの言語仕様が定めていない解析規則を、設定で追加することは行いません。次のIssueは、
この判断と検討内容を残す記録として保留します。

* https://github.com/KeishiS/adocweave/issues/384[利用側アプリ用の文書属性の接頭辞の予約]

同じ文書が設定によって異なる意味を持つ状態を作らないためです。AdocWeaveは、文書の意味を
文書自身と言語仕様だけから決めます。仕様が組込み属性として定めた名前は、設定にかかわらず
仕様どおりに解釈します。

利用側アプリが定める属性は、現在も組込みの意味を与えずに属性環境へ保持します。名前が
利用側アプリのものであることは、その名前を決めた利用側アプリが知っています。AdocWeaveが
接頭辞を設定として受け取っても、解釈を変えない点は同じです。
