= ADR 0008: 現行情報に限定した文書管理
:status: accepted

== 文脈

codeの更新に対して文書の改訂が遅れると、同じ情報を記載した複数の文書が互いに矛盾する。
特に、versionごとの移行文書、作業手順および実装から取得できる一覧は、更新のたびに保守が必要となる。
このrepositoryでは古いversionとの互換性を維持せず、過去の利用方法をrepository内の文書として
保持する必要もない。

== 決定

repository内の文書は、現在の利用方法と現行仕様を説明するために必要なものへ限定する。
新しい文書を追加する前に既存文書への統合を検討し、情報の正本を次のように分ける。

* 現行仕様と利用方法は`docs`ディレクトリに記載する。
* 複数の機能や今後の変更へ影響する設計判断とその理由はADRに記載する。
* 実装予定、調査および一時的な作業記録はGitHub Issuesで管理する。
* version固有の変更内容と移行手順はGitHub Release Notesに記載する。
* codeや機械可読なmanifestから取得できる情報は、原則として文書へ複製しない。

古いversion専用の文書は維持しない。文書の再編時には、現在も必要な情報だけを適切な正本へ移し、
過去の経緯だけを記録した文書は削除する。

== 帰結

利用者がrepository内で参照する文書は、原則として現在のcodeに対応する。過去のversionに固有の変更は
GitHub Release Notesを参照する必要がある。設計の経緯をすべて保存することよりも、現在の仕様を
正確かつ少ない文書で維持することを優先する。

ADRはすべての変更について作成せず、長期的に参照する設計判断に限定する。現行仕様が変わった場合は
該当する仕様文書を更新し、判断を置き換える必要がある場合は新しいADRから置換対象を明示する。
