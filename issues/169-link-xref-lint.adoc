= linkとxrefの使い分けに対するLint
:status: planned
:depends-on: 031

== 目的

AsciiDoc文書への通常linkと、AsciiDoc以外のfileへのxrefを検出し、用途に合うmacroを選べるよう
位置付きのwarningを返します。fileの実在検査とは分離し、filesystemへアクセスしない通常の
`adocweave check`で検出します。

== 対象

次の組み合わせを検出します。

* `.adoc`または`.asciidoc`を指すschemeなしの通常link
* `.json`、`.toml`、`.pdf`など、AsciiDoc以外の拡張子を明示した文書間xref

外部URL、任意schemeのxref、文書内anchor、拡張子を省略した文書間xrefおよび属性展開を
確定できないtargetは対象外とします。queryとfragmentは拡張子の判定前に分離します。

== 診断

診断codeは用途を区別できる次の二つとします。

* `asciidoc-file-link`
* `non-asciidoc-xref`

いずれも既定ではwarningとし、target全体ではなくmacro名または修正対象となる範囲を示します。
messageは説明用とし、自動処理では安定した診断codeを使用します。

== 修正候補

schemeなしの相対targetで、macroの置換後もlabel、fragmentおよび属性listを保持できる場合だけ、
`link`と`xref`を置き換える`Always`の修正候補を返します。外部URL、属性展開を含むtargetまたは
解釈が変わる可能性がある入力には自動修正を返しません。

== 実在検査との関係

xref:168-cli-local-target-validation.adoc[Issue 168]はlocal targetの実在とproject root境界を検査します。
このIssueはmacroの意味とtarget種別の組み合わせだけを検査し、`--local-targets`、`--include`および
file I/Oへ依存しません。

== 完了条件

* `LintRule`へ二つの規則と安定した診断codeを追加します。
* 通常link、URL macro、文書内xref、文書間xref、任意scheme xrefおよび属性展開の正例と反例を
  unit testで確認します。
* `.adoc`、`.asciidoc`、拡張子省略、query、fragmentおよび大文字小文字の扱いを固定します。
* human出力、JSON出力およびLSP診断で同じcode、severityおよびrangeを返します。
* xref:../docs/user-guide/command-line.adoc#diagnostics[問題の確認]へ新しいwarningの意味を記載します。

== 非目標

* target fileの存在、別文書内anchor、外部URLの到達性またはcontent typeを検査しません。
* URLの末尾が`.adoc`であることだけを理由に、外部URLの通常linkを拒否しません。
* 拡張子を持たないfileがAsciiDocかどうかを推測しません。
