= v0.6.2 release readinessとCI公開経路の受け入れ
:status: completed
:depends-on: 157, 159

== 目的

Dependabotによる依存更新と、成功済みmain candidateのtag公開時再利用を`v0.6.2`として受け入れる。
公開API・AsciiDoc意味・配布対象を変えず、公開経路の検証範囲と待ち時間を改善する。

== 完了条件

* workspace、Zed、browser、protocol、release manifest、distribution planおよびfixtureが`0.6.2`で一致する。
* main pushでquality、fuzz、native／browser／Zed build、candidate verificationおよびLinux 2 architectureの導入E2Eが成功する。
* `v0.6.2` tagが同じcommitの成功済みcandidateを再利用し、source quality、fuzz、archive buildおよび導入E2Eを再実行しない。
* GitHub Releaseがstableであり、計画どおりの9 asset、checksum、SBOMおよびprovenanceを持つ。

== 終了結果

`v0.6.2`のtagとGitHub Releaseは作成しなかった。Dependabot導入とcandidate artifact再利用の受け入れを
patch releaseとして独立させず、後続の`v0.7.0` release trainへ統合したためである。

Issue 157のDependabot導入は初回更新群と最終main CIで受け入れ、Issue 159のCI公開経路は
`v0.7.0`のmain candidate run 30158770759とtag publication run 30159071293で受け入れた。
したがって、このIssueは`v0.6.2`を公開したという意味ではなく、計画したrelease trainを後続releaseで
代替して終了したものとして完了する。
