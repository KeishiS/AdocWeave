= Language Server Protocol 3.18適合性監査
:status: completed
:depends-on: 038, 069

== 目的

https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/[Language Server Protocol 3.18]
を基準として、AdocWeave LSPの実装、capability negotiation、通知購読および応答形式の乖離を
再現可能な一覧にする。optional機能を網羅的に実装するのではなく、対応、非対応および意図的な
非目標を区別し、既存clientとの相互運用性に影響する差分だけを後続実装へ結び付ける。

監査基準は2026-07-25に参照した
https://github.com/microsoft/language-server-protocol/tree/b7f5132c95261c0898ae5124e7a91707abc48fcd/_specifications/lsp/3.18[
`microsoft/language-server-protocol`の`gh-pages` commit
`b7f5132c95261c0898ae5124e7a91707abc48fcd`]とする。公開仕様siteは
https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/[
Language Server Protocol 3.18]である。

== 監査結果

=== capability matrix

[cols="2,2,5",options="header"]
|===
|仕様領域 |状態 |AdocWeaveの仕様

|initialize、initialized、shutdown、exit
|対応
|initialize前のrequestは`ServerNotInitialized`、重複initializeとshutdown後のrequestは
`InvalidRequest`とする。initialize前とshutdown後の通知を破棄し、shutdown後のexitだけを
終了status 0とする。それ以外のexitはstatus 1で終了する。

|client process
|対応
|`processId`が指定された場合は`async-lsp`のclient process monitorを有効にし、client終了を監視する。
`processId: null`では監視しない。

|position encoding
|対応
|`general.positionEncodings`からUTF-8またはUTF-16をclientの優先順で選ぶ。共通候補がなければ
仕様既定のUTF-16を使う。UTF-32は非目標とする。

|text synchronization
|対応
|open／close、incremental changeおよびsaveを静的に広告する。複数change、CRLF、UTF-8／UTF-16、
generation gateおよびcancellationを既存testで固定する。

|workspace folders
|条件付き対応
|`workspace.workspaceFolders`がtrueのclientにだけ
`workspace.workspaceFolders.supported`と`changeNotifications`を広告する。
初期folder集合と`workspace/didChangeWorkspaceFolders`を扱い、open overlayを再適用する。
対応clientが`workspaceFolders: null`を送った場合は空集合であり、deprecatedな`rootUri`へ
fallbackしない。未対応clientに限り`rootUri`を使い、nullの場合はdeprecatedな`rootPath`へ
fallbackする。

|watched files
|条件付き対応
|`workspace.didChangeWatchedFiles.dynamicRegistration`がtrueの場合、initialized後に
`client/registerCapability`で`**/*.adoc`のcreate／change／deleteを登録する。
登録失敗はserverを終了させず、watcherなしで継続する。未登録clientから届いた通知も
workspace境界とresource上限を再検査して安全に処理する。

|Hover
|対応
|`contentFormat`の優先順にMarkdownまたはPlain Textの`MarkupContent`を返す。
capabilityがなければlegacy `MarkedString`互換のplain文字列を返す。

|Document Symbol
|対応
|`hierarchicalDocumentSymbolSupport`がtrueの場合だけ`DocumentSymbol[]`を返し、
それ以外は階層をpre-orderで平坦化した`SymbolInformation[]`を返す。

|Code Action／Workspace Edit
|条件付き対応
|literal supportの`valueSet`に`quickfix`がある場合だけproviderを広告し、`CodeAction`を返す。
requestの`range`と`context.only`を適用する。`isPreferred`、version付き`documentChanges`は
対応capabilityがある場合だけ使い、それ以外は`changes`へfallbackする。Command形式、
resolve、data、disabled、documentation、tagsおよびchange annotationは非目標とする。

|push diagnostics
|対応
|`versionSupport`がtrueの場合だけversionを含める。pull diagnosticsとdiagnostic refreshは
非目標とする。

|Document Link
|対応
|`tooltipSupport`がtrueの場合だけtooltipを含める。resolveは広告しない。

|Semantic Tokens
|条件付き対応
|clientがfull request、relative formatならびに`string`と`variable` token typeをすべて
扱える場合だけfull providerを広告する。range、deltaおよびrefreshは非目標とする。

|Completion
|対応
|基本`CompletionItem[]`だけを返す。resolve、snippet、insert／replace edit、label details、
item defaultsおよび3.18 apply kindは非目標とする。

|Definition、References、Rename
|対応
|`Location`／`Location[]`と`WorkspaceEdit`の基本形を使う。Location Link、prepare rename、
default behaviorおよびresolveは非目標とする。

|Formatting
|対応
|文書全体のformattingだけを広告する。range、on-typeおよび3.18のmultiple document rangesは
非目標とする。

|3.18 optional追加機能
|非目標
|inline completion、text document content、folding range refresh、notebook同期、
file operation、call／type hierarchy、inlay hint、inline value、linked editing、
selection range、monikerおよびworkspace symbolは今回の適合条件に含めない。

|transport
|意図的制約
|製品binaryはstdioだけを提供する。in-memory transportはprotocol testに使う。
network socketまたは独自framingは非目標とする。
|===

=== protocol libraryの判断

`async-lsp 0.2.4`と、その公開型で解決される`lsp-types 0.95.1`を維持する。今回必要な
client capability、server capability、registrationおよび応答unionはこの組合せで型付きに
表現できる。`async-lsp`の既定lifecycleはinitialize前／shutdown後の通知を転送し、
shutdown前のexitを異常終了にできないため、AdocWeave所有の小さなlifecycle state machineへ
置き換える。3.18 optional機能を実装するまで、meta model全体を局所的なJSON型として複製しない。

=== JSON-RPC 2.0境界

2026-07-25にhttps://www.jsonrpc.org/specification[JSON-RPC 2.0 Specification]も参照した。
LSP 3.18はcontent部にJSON-RPC 2.0を使用する一方、JSON-RPC batch messageを明示的に禁止する。

[cols="2,2,5",options="header"]
|===
|項目 |状態 |判断

|version、request、response
|対応
|`jsonrpc`は常に`"2.0"`とする。LSPの`RequestId`に従って整数または文字列の`id`を受け、
responseへ同じ値を返す。成功responseは`result`、失敗responseは`error`の一方だけを持つ。

|notification
|対応
|notificationにはresponseを返さない。未知の`$/`通知はLSP規則に従って無視する。
既知通知のparams不正または未知の通常通知は、文書同期を失ったまま継続しないよう
`async-lsp`のfail-closedな接続終了を維持する。

|error code
|対応
|未知requestは`MethodNotFound`（`-32601`）、既知requestの不正paramsは`InvalidParams`
（`-32602`）とし、requestの`id`を保持する。lifecycle固有errorはLSPの規則を優先する。

|batch
|非対応
|JSON-RPC 2.0ではoptionalだが、LSP 3.18が禁止するため受け付けず、送信もしない。

|malformed JSON／invalid request object
|library制約
|`async-lsp 0.2.4`のcodecはdeserialize errorで接続をfail-closedに終了し、JSON-RPCの
`ParseError`／`InvalidRequest` responseを合成しない。正常なLSP peerとの相互運用性に
影響せず、framingとdispatchを再実装するriskに見合わないため今回は維持する。

|framing
|対応
|UTF-8 JSONとbyte単位の`Content-Length`を使う。製品はstdio、testは同じMainLoopを
in-memory streamで使用する。
|===

== 監査で確認した乖離

監査開始時にはwatched filesの動的登録、workspace folder変更、Hover、Document Symbol、
Workspace Edit、Code Action、diagnosticsおよびDocument Linkのcapability negotiationが不足していた。
これらはcapability matrixと実装記録に示す仕様へ修正した。

stdio transportは意図的な制約として維持し、client process監視は`async-lsp`の
`client-monitor` featureで有効化した。LSP 3.18 optional機能は、相互運用性に必要な範囲と
非目標をmatrixで区別した。

== 作業

* 3.18のserver capability、client capability、request、notificationおよびlifecycleを
  「対応」「部分対応」「非対応」「非目標」のmatrixへ整理する。
* 初期化で合意したclient capability profileを保持し、応答形式とworkspace通知購読へ反映する設計を定める。
* file watcherの動的登録、workspace folder変更およびclient別のHover、Document Symbol、
  Code Action／Workspace Edit応答を検証する。
* `async-lsp 0.2.4`と解決される`lsp-types 0.95.1`の3.18対応範囲を評価し、更新または局所的な
  protocol表現の判断を記録する。
* 最小capability clientと全対応clientのfixtureを用意し、in-memory transport testで
  initializeからshutdown／exitまでを固定する。
* lifecycle、UTF-8／UTF-16位置、incremental sync、generationおよびcancellationの既存保証を
  regression testとして維持する。
