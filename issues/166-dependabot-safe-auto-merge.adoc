= Dependabot PRの安全な自動merge
:status: planned
:depends-on: 157

== 目的

定型的で低riskなDependabot Pull Requestだけを、既存のbranch protectionと品質・供給網検査を
迂回せず自動mergeできるようにする。GitHub Issue
https://github.com/KeishiS/AdocWeave/issues/19[#19]を外部実行trackerとし、この文書を
repository内の設計・受け入れ基準とする。

== 設計制約

* actor、Dependabot branchおよびdependency metadataをすべて確認し、通常のPull Requestを対象にしない。
* major update、競合、失敗または未完了check、要求review未充足およびrelease freeze中は自動mergeしない。
* RustSec、license／source policy、duplicate dependency、fuzz、Nixおよび必須checkを迂回しない。
* broad write permission、長期credentialおよびfork由来codeへ渡るsecretを導入しない。
* GitHubのauto-mergeまたはmerge queueを利用し、独自workflowによる即時mergeを避ける。

== 作業

* ecosystem、SemVer範囲、dependency種別および許可するupdate typeのpolicyを明示する。
* branch protection／ruleset、required checks、review ruleおよびGitHub Actions permissionを監査する。
* metadata不正、major update、check失敗、競合およびrelease freezeのnegative testを用意する。
* 自動mergeの判定理由と結果をActions log、Pull Request labelまたはcheckへ監査可能な形で残す。
* dependency governanceとrelease workflowへ停止・復旧・手動override手順を記載する。

== 完了条件

* 許可済みのDependabot updateだけが、最新の`origin/main`と全required checks成功後に自動mergeされる。
* 拒否条件のいずれかを満たすPull Requestはopenのまま理由を表示する。
* workflow permissionとsecret境界が最小で、repository外codeによる権限取得経路がない。
* policy testと実際のDependabot Pull Requestによる段階的な受け入れ結果が記録される。
