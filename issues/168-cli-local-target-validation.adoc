= CLIによるlocal targetの実在検査
:status: planned
:depends-on: 070,150

== 目的

文書の移動や削除に伴う参照更新漏れをCIで検出するため、CLIの`check`へ明示的な
local target実在検査を追加する。xrefだけでなく、通常link、media resourceおよびincludeを
同じpath policyで検査し、存在しないfileやproject root外への参照を位置付きで報告する。

== 設計判断

`adocweave check --local-targets --project-root DIR <document>`を入口とする。既定の`check`は
file I/Oを増やさず、option指定時だけCLI adapterがlocal filesystemを検査する。coreは引き続き
host非依存とし、解析中にI/Oを行わない。

対象は次のとおりとする。

* `xref:other.adoc[]`および`xref:other.adoc#anchor[]`のdocument target
* `link:manual.pdf[]`など、schemeを持たない相対link
* `image`、`icon`、`audio`および`video` macroの相対resource target
* `include::part.adoc[]`の相対target

文書内anchor、任意scheme xref、絶対URL、protocol-relative URLおよびdata URLはfilesystem検査の
対象外とする。外部URLへnetwork requestを送らない。初期実装では別文書内のanchor実在性を
検査せず、target fileの実在だけを保証する。

相対targetは参照元documentの親directoryから解決する。`..`を一律禁止せず、正規化後のpathが
`--project-root`内にあることを必須とする。symlinkを解決した結果がroot外になる場合も拒否する。
queryとfragmentを持つ通常linkはfilesystem pathと分離して扱い、属性展開失敗など安全にpathへ
変換できないtargetを黙って成功させない。

== 診断と終了状態

人間向け出力と`--json`の両方で、参照元path、行、列、targetおよび次の分類を返す。

* `local-target-missing`
* `local-target-outside-root`
* `local-target-not-file`
* `local-target-permission-denied`
* `local-target-unverifiable`

一件でもerrorがあれば終了codeを非0とする。同じtargetへの重複参照は各source位置を保持するが、
filesystem accessは正規化済みpathごとに一度だけ行う。検査件数へ上限を設け、巨大文書による
無制限なfilesystem accessを防ぐ。

== `--include`との関係

`--include`はresourceを読み込んで展開するoption、`--local-targets`は参照先の実在だけを検査する
optionとして責務を分ける。両方を指定した場合、include targetを重複して読み込まない。
`include::missing.adoc[optional]`の扱いはpreprocessorのoptional notice仕様と一致させる。

== CIへの統合

`cargo make adoc-check`は追跡対象のAsciiDocを次の形で検査し、削除・移動後に残った参照を
merge前に拒否する。

[source,console]
----
adocweave check --local-targets --project-root . <document>
----

== 完了条件

* 公開解析結果からxref、通常link、media resourceおよびinclude targetを型付きで列挙し、
  文字列の正規表現抽出に依存しない。
* file入力と標準入力について、参照元基準directoryとproject rootの組み合わせを明示する。
* human／JSON診断と終了codeを固定し、missing、root外、directory、権限不足および検査不能を
  CLI統合testで確認する。
* 外部URL、任意scheme xref、文書内anchorおよびescaped／不完全な構文を誤ってfilesystemへ
  解決しない。
* Unix symlink escape、同一targetの重複、検査件数上限および`--include`併用をsecurity testで
  確認する。
* `cargo make adoc-check`へopt-in検査を組み込み、存在するtargetのfixtureと欠落targetの回帰testを
  追加する。
* xref:../docs/command-line.adoc[コマンドラインの使い方]と
  xref:../docs/testing.adoc[テストの実行]へoption、対象範囲、非対象およびCIでの扱いを記載する。

== 非目標

* 外部URLの到達性、HTTP status、redirectまたはTLSを検査しない。
* local resourceをHTMLへ埋め込んだり、link targetを書き換えたりしない。
* 初期実装では別文書のanchor、HTML fragmentまたはPDF内部の参照先を検査しない。
