= Macro境界のLint
:status: planned
:depends-on: 047, 065, 170

== 目的

対応済みmacroに見える記述が開始境界の条件だけを満たさず、通常のtextとして解釈された場合に、
位置付きのwarningを返します。`xref:`だけでなく、`link:`、`image:`など同じ境界規則を持つ
inline macroを共通の仕組みで検査します。

AsciiDoc仕様への適合性を断定する検査ではなく、AdocWeaveの認識規則に対する記述ミスの検出として
扱います。このため、ruleは既定で無効とします。

== CLI

[source,console]
----
adocweave check --enable-rule macro-boundary document.adoc
----

`--enable-rule`は安定した診断codeを受け取る反復可能なoptionとします。存在しないcode、または
利用者が有効化できないcodeはusage errorとします。`macro-boundary`を指定しない通常の
`adocweave check`では、このruleによるwarningを返しません。

Issue 170のrule一覧では、`macro-boundary`を`enabledByDefault: false`として公開します。

== 検出対象

置換が有効な文脈で、次の条件をすべて満たす候補を検出します。

* AdocWeaveが対応するinline macroまたは自動linkの完全な構文
* macroごとに定めた開始境界だけを満たさない候補
* escapeされていない候補

初期対象には、共通のtoken境界を使用する`xref:`、`link:`、inlineの`image:`、標準macro、
URLおよびemailを含めます。対応済みmacroの追加時に検査対象の登録を忘れないよう、inline
recognizerと同じ定義から境界規則を取得します。

次の入力は検出対象です。

[source,asciidoc]
----
本文xref:other.adoc[参照先]
本文link:asset.json[データ]
本文image:figure.png[図]
----

次の入力は対象外です。

* 行頭または許可されたtoken境界から始まるmacro
* source block、literal block、commentおよび置換が無効な文脈
* escapeされたmacro表記
* 完全なmacro構文にならない説明用の`xref:`などの文字列
* 境界を要求しない`<<id>>`などの短縮記法
* `include::`およびblockの`image::`などのblock macro

block macroに開始位置の検査が必要な場合は、inline macroと異なる文脈規則を持つため別ruleとして
扱います。

== 診断

診断codeは`macro-boundary`とし、境界を満たさないmacro名の範囲を示します。

[source,text]
----
document.adoc:3:3: warning[macro-boundary]: inline macro must start at a token boundary
----

messageには検出したmacro名と、許可された開始位置を簡潔に含めます。自動処理ではmessageではなく
安定した診断codeを使用します。

空白の挿入だけで意味が一意になる場合は、`MaybeIncorrect`の修正候補を返します。CJK文章、
punctuationおよび属性展開の前後など、意図を確定できない入力には自動修正を返しません。

== 実装方針

source全体の単純な文字列検索は行いません。inline recognizerがmacro候補の構文を確認した後、
開始境界だけを理由に候補を棄却する箇所で構造化されたsyntax issueを記録し、Lintで
`macro-boundary`へ変換します。

候補の走査回数と入力上限は既存のinline解析に含め、Lintを有効にしても入力長に対する線形時間と
既存の診断件数上限を維持します。human出力、JSON出力およびLSP診断は同じcode、severityおよび
source rangeを使用します。

== 完了条件

* `--enable-rule macro-boundary`によるopt-inのwarning
* `xref:`、`link:`、`image:`、標準macro、URLおよびemailの境界fixture
* 空白、行頭、許可されたpunctuation、CJK文字、escapeおよび不完全macroの正例と反例
* source block、literal block、commentおよび置換設定に応じた抑制
* human出力、JSON出力およびLSP診断における同一の診断情報
* `--list-rules --json`における既定無効ruleとしての掲載
* xref:../docs/user-guide/command-line.adoc#diagnostics[問題の確認]へのoptionとwarningの説明

== 非目標

* AsciiDoc仕様がすべてのmacroへ共通の空白要件を定めているとの判定
* macro targetの実在性、到達性または用途の検査
* block macroの行頭および開始位置の検査
* 任意のplain textから不完全なmacroの意図を推測する処理
