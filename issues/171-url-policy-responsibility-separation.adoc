= URL検査の責務分割
:status: planned
:depends-on: 031

== 目的

URLの構文、安全なHTML出力、local fileの境界および実在性を別々の検査として扱います。
AsciiDocで有効な`../`を含む相対linkや文書間xrefを、filesystem情報なしに一律拒否しません。

== 検査の分類

検査を次の責務へ分けます。

* 制御文字、不完全なschemeおよび不正なencodingなどの構文検査
* `javascript:`や許可していない`data:` URIなど、activeなHTML出力に対するscheme検査
* `..`、絶対pathおよびsymlinkを正規化した後のproject root境界検査
* fileの欠落、directory、権限不足および検査不能を扱う実在検査
* 利用側アプリが渡した解決済みURLに対する`RenderPolicy`の検査

構文検査は常に有効とします。HTML出力のscheme検査は安全側の既定値を維持します。project root境界と
実在性は、Issue 168の`--local-targets --project-root DIR`を指定した場合だけ有効にします。

== Lintと変換の分離

`adocweave check`は、filesystemへアクセスしない既定動作で通常の相対linkと文書間xrefを許可します。
相対targetに`..`が含まれることだけを理由に`invalid-url-scheme`または
`invalid-cross-reference`を返しません。

HTML変換では、文書に書かれたURL、Resolverが返したURLおよびresource URLを別のcontextとして検査します。
Lintとrendererが一つのbooleanや同じ拒否理由を共有せず、用途ごとのpolicyを型で区別します。

== 設定

利用側アプリ向けAPIでは、少なくとも次を独立して設定できるようにします。

* 許可scheme
* authored relative URLの許可
* resolved relative URLの許可
* resolved root-relative URLの許可
* data URIの許可
* local targetのproject root境界と実在検査

CLIでは安全性検査全体を無効にするoptionを設けず、必要な検査だけを明示的に有効化します。
設定の組み合わせと既定値はJSON、nativeおよびWASMで一致させます。

== 移行

このIssueが完了するまで、repository文書内の`../`を含む相対linkに対する
`invalid-url-scheme`はCIの限定的なallowlistへ登録します。他の診断codeや別文書の同じcodeを
無差別に無視しません。実装後はallowlistを削除します。

== 完了条件

* URL構文、scheme、local境界、実在性およびrenderer入力の検査責務を型とmoduleで分離します。
* `link:../release-manifest.json[]`と`xref:../guide.adoc[]`をfilesystem accessなしで解析・Lintできます。
* `javascript:`、encoded control、network-path referenceおよび許可していないdata URIの拒否を維持します。
* Issue 168のlocal target検査を有効にした場合だけ、正規化後のroot escapeとsymlink escapeを拒否します。
* native、WASM、CLIおよびHTMLの正例と反例を共通fixtureで確認します。
* 一時的なCI allowlistを削除し、相対linkを含む規範文書が無診断になります。

== 非目標

* 外部URLの到達性、HTTP status、redirectまたはTLSを検査しません。
* HTML変換で危険なschemeを既定で許可しません。
* すべての安全性検査を一括で無効化するoptionを追加しません。
