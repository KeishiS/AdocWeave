= Fixture

fixtureは担当機能ごとに分類する。各機能ディレクトリには次のファイルを配置できる。

- `*.adoc`: ソース文書
- `*.html`: 期待するHTML断片
- `*.diagnostics.json`: 期待する診断
- `*.formatted.adoc`: 期待するFormatter出力

各fixtureは一つの動作へ集中させる。内容を表す名前を使い、正常、不正、不完全、境界値の
入力を別ファイルとして追加する。

`release/core.adoc`は機能横断のコアリリースfixtureである。期待HTMLを同じディレクトリへ
置き、CLI、Lint、Formatterのテストで同じソースを使う。

runtime横断fixtureのmanifestは、core crateが所有するruntime間の公開仕様として
`../crates/adocweave/conformance/cases.json`に置く。manifest内の`sourceFile`と
`expectedFile`は、manifestの所在ではなくfixture rootである`fixtures/conformance/`を
基準に解決する。
各caseには互換性分類、差分理由および仕様versionへの影響判断を記録しなければならない。
native、WASMおよびLSPはこのmanifestまたは参照先の同じソースを使用し、別内容の
複製fixtureを作らない。個別のfixtureは、他のcaseの入力や期待出力へ依存せず、
そのfixtureだけで一つの動作を検証できる内容にする。

`conformance/consumers.json`は、リポジトリ内のreaderが使用するmanifest pathと
fixture rootの単一の設定源であり、このmanifestを直接読む処理の一覧でもある。
`capabilities`は各readerがmanifestだけを使うか、参照先fixtureも読むかを示す。
core crateはsource packageへ埋め込むmanifestだけを使い、その他のreaderはこの設定を
読み込んでmanifestとfixture rootを別々に解決する。新しいreaderを追加するときは、
同じ変更でこの一覧へpathとcapabilityを追加する。

`public-conformance.json`は、利用側の適合性試験で再利用する公開fixtureのmanifestである。
各caseで入力、投影、HTML、解析診断、描画診断、適用profileおよび対象構文を一つの対応として示し、
manifest全体で``outputContractVersion``とlicenseを示す。各caseの`stableContract`だけを利用側が
依存できる範囲とし、比較用file全体のbyte列、`implementationDetails`および
`globalImplementationDetails`に列挙した表現はリポジトリ内の回帰検査に限定する。
Manifest、参照するAsciiDocおよび期待出力を含む公開fixture一式は、リポジトリのrootの
link:../LICENSE-MIT[MIT License]またはlink:../LICENSE-APACHE[Apache License 2.0]の条件で
再利用できる。

`schemaVersion`はmanifest形式の非互換変更、`outputContractVersion`は`stableContract`の
非互換変更で更新する。公開仕様を変更するときは、manifest、参照する期待出力およびRelease Notesを
同じ変更で更新する。公開仕様に含まれない空白、属性順または未選択の投影fieldだけを変更する場合は
`outputContractVersion`を更新しない。

`syntax-support.json`は、対応表、互換性評価、文法および対応するfixtureの同期を検査するための
manifestである。人向けの仕様は`docs/`に記載し、このファイルへ説明文を重複させない。

`html/validation.json`はHTML5標準適合性検査の対象、固定validator設定およびnegative fixtureを管理します。
断片出力は`html/validation-template.html`の一意なmarkerへ挿入し、完全HTML文書として検査します。
検査時に生成する文書は`target/html5/`へ出力し、fixtureディレクトリへ書き戻しません。
